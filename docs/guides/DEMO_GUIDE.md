# SK-TASK 실제 화면 시연 순서

2026-09-11 개편 화면 기준이다. 상품은 클라인즈 114,000원·LG 169,000원, 무료배송인 모의 자료를 사용한다. 상품 자료를 바꾸면 아래 기대 금액도 다시 확인한다.

## 시연 전 준비

1. [프로젝트 README](../../README.md)에 따라 앱을 실행한다.
2. AI 시연에는 프로젝트 `.env`의 유효한 OpenAI 키가 필요하다. 양식 작성·규정 계산·문서 생성은 AI 연결 없이도 사용할 수 있다.
3. 기본 시연에서는 희망 사양을 비워둔다. 상품 근거에 없는 사양을 입력하면 제출이 제한될 수 있다.
4. 구매 목적에 `시연-정상`, `시연-예산초과`처럼 구별할 이름을 적는다.
5. 왼쪽 아래 **시연 설정 → 시연 프로필 · 인증 아님**에서 역할을 바꾼다.

| 화면의 사용자       | 내부 프로필 | 역할        |
| ------------------- | ----------- | ----------- |
| 박직원 · 개발팀     | employee_a  | 요청 직원 A |
| 김직원 · 운영팀     | employee_b  | 요청 직원 B |
| 이담당 · 구매팀     | buyer_a     | 구매 담당자 |
| 최승인 · 경영지원팀 | manager_a   | 추가 승인자 |

실제 주문·결제·사내 시스템 전송은 하지 않는다. 제출과 결재는 로컬 SQLite에 기록된다. [상품 자료](../reference/COUPANG_FIXTURES.md)와 [API 계약](../reference/COUPANG_API_CONTRACT_CHECK.md)을 참고한다.

## 화면 길찾기

- **내 업무**: 내가 처리할 요청과 최근 생성한 내 요청 5건.
- **+ 새 구매요청**: 새 양식과 새 AI 대화 시작. 기존 요청을 다시 여는 버튼이 아니다.
- **내 구매요청**: 검색·부서·제출일 필터로 내 요청 찾기.
- **결재 대기**: 구매 담당자와 추가 승인자에게만 표시.
- **완료 문서**: 승인 완료·반려 요청 조회.
- **구매요청 상세**: 구매 조건 → 상품 선택 → 검토 및 제출. 오른쪽 AI 도우미와 같은 요청을 수정한다.
- **결재 검토**: 담당자가 문서와 금액을 확인하고 승인·보완 요청·반려한다.

AI 패널은 **AI 도우미** 스위치로 접을 수 있다. 같은 브라우저 세션에서 목록으로 나갔다가 요청을 다시 열면 그 요청의 대화가 남는다. 새로고침·서버 재시작 뒤에도 남는 것은 DB의 업무 데이터이며 대화는 아니다. 사용자 전환·화면 이동은 대기 중인 제출 확인을 취소한다.

## 1. AI 검색 → 직접 선택 → AI 수정 → 제출

설계 연결: TS-01-C001/C002, TS-04-C002, TS-05-C001, TS-06-C001.

1. **박직원 → + 새 구매요청**. 양식 옆 **AI 요청**에 다음 문장을 입력하고 **AI에게 요청**.

   > 모니터 3대, 배송비 포함 예산 60만원, 목적은 시연-AI 신입 개발자 장비 지급이야. 모니터 후보를 찾아줘.

2. 상품 선택 화면으로 연결되면 클라인즈 카드의 **이 상품 선택**. 총액 **342,000원**, 버튼 **선택됨**을 확인한다.
3. 같은 화면의 AI에 다음 문장을 보낸다.

   > 선택 상품과 목적은 유지하고 수량만 4대로 바꿔줘. 규정 검토 후 문서 3종을 만들어줘. 제출하지마.

4. 수량 **4대**, 총액 **456,000원**, 남은 예산 **144,000원**과 문서 3개 탭을 확인한다.
5. **내 구매요청 → 대상 요청 열기**로 이동해도 대화와 문서가 이어지는지 확인한다.
6. AI에 `제출해줘` → 공통 **구매요청 제출 확인** 창 → **취소**. 제출 준비 상태와 문서가 유지되어야 한다.
7. 다시 `제출해줘` → 금액·수량·결재 경로를 확인하고 **제출**.
8. **구매팀 검토 중**을 확인한다. 아래 공통 결재 절차로 마친다.

AI 모델 응답은 변동될 수 있다. 중간에 조건 보완을 요청하면 내용을 확인하고 같은 요청에서 이어간다. 제출은 사용자가 확인 창에서 누르기 전까지 진행되지 않는다.

## 2. 양식으로 정상 구매요청

1. **박직원 → + 새 구매요청**. AI 도우미는 접어도 된다.
2. 수량 `3`, 예산 `600000`, 구매 목적 `시연-정상 신입 개발자 장비 지급`, 희망 사양 비움.
3. **저장하고 상품 찾기** → 클라인즈 카드의 **이 상품 선택**.
4. 필요하면 **쿠팡 상품 보기**, **가격·사양 상세**를 확인한다. 외부 페이지의 현재 가격은 모의 자료와 다를 수 있다.
5. **검토하고 문서 만들기 →**. 총액 **342,000원**, 예산 **600,000원**, 남은 예산 **258,000원**.
6. **구매요청서 / 상품 비교표 / 규정 검토**를 읽고 **구매팀에 제출 → 제출**.
7. 아래 공통 결재 절차로 **승인 완료**까지 확인한다.

### 공통 결재 절차

1. **이담당 → 결재 대기 → 대상 요청 열기**. 요청이 많으면 제목으로 조회한다.
2. **결재 검토**에서 금액과 문서를 확인한다.
3. **승인 → 확인하여 처리**. 승인은 의견 없이 가능하다.
4. 일반 요청은 **승인 완료**, 100만 원 이상 요청은 **추가 승인 대기**가 된다.

문서 탭의 **다운로드**는 저장된 Markdown 문서를 받는다. 화면 미리보기는 같은 요청의 구조화 데이터를 읽기 좋게 표현하며, **저장된 문서 원문**에서 다운로드 대상의 원문을 확인할 수 있다.

## 3. 예산 초과 → 수정 → 과거 버전

1. 새 요청: 수량 `4`, 예산 `400000`, 목적 `시연-예산초과`.
2. **저장하고 상품 찾기 → 클라인즈의 이 상품 선택 → 검토하고 문서 만들기 →**.
3. 총액 **456,000원**, 남은 예산 **-56,000원**, 예산 초과 안내와 비활성화된 **구매팀에 제출** 확인.
4. **구매 조건 보완 → 예산 500000 → 구매 조건 저장 → 검토하고 문서 만들기 →**.
5. 제출 가능 상태를 확인한다.
6. **요청 정보 · 이전 버전 → 조회 버전**에서 변경 전 버전을 선택한다. 과거 문서가 보존되고 AI 입력·제출·수정 버튼이 없어야 한다. 이후 최신 버전으로 돌아온다.

## 4. 100만 원 이상 → 추가 승인

1. 새 요청: 수량 `6`, 예산 `1100000`, 목적 `시연-추가승인`.
2. **저장하고 상품 찾기 → LG 카드의 이 상품 선택 → 검토하고 문서 만들기 →**.
3. 총액 **1,014,000원** → **구매팀에 제출 → 제출**.
4. **이담당 → 결재 대기 → 열기 → 승인**. 추가 승인 안내 확인 → **확인하여 처리**.
5. **추가 승인 대기** 확인.
6. **최승인 → 결재 대기 → 열기 → 승인 → 확인하여 처리**.
7. **승인 완료** 확인. 구매 담당자의 승인만으로 끝나면 안 된다.

## 5. 보완 요청·반려·사용자 분리

| 항목                | 화면 조작                                                              | 기대 결과                                                      |
| ------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| 목적 없는 초안      | 양식에서 목적을 비우고 상품 선택·문서 생성                             | 문서가 있으나 제출 불가                                        |
| 목적 보완           | **구매 조건 보완** → 목적 입력 → 저장 → 문서 재생성                    | 새 버전에서 제출 가능                                          |
| 보완 요청           | 직원 제출 → 이담당으로 열기 → **보완 요청**                            | 의견이 비면 **확인하여 처리** 비활성화                         |
| 보완 후 재제출      | 의견 입력·처리 → 박직원 **내 업무**에서 열기 → **구매 조건 보완**      | 담당자 의견 표시, 수정 후 재검토·재제출 가능                   |
| 반려                | 이담당으로 제출된 요청 열기 → **반려** → 의견 입력 → **확인하여 처리** | 반려 상태와 처리 의견 보존                                     |
| 사용자 분리         | A의 요청 제목을 기록 → 김직원 **내 구매요청**에서 조회                 | A의 요청이 목록에 보이지 않음                                  |
| 새 요청의 대화 분리 | 대화 후 **+ 새 구매요청**                                              | 새 화면에 이전 대화 없음. 기존 요청을 다시 열면 해당 대화 유지 |
| 지원 범위 밖        | 새 요청의 AI에 `점심 메뉴 추천해줘`                                    | 모니터 구매 지원 범위 안내                                     |
| 조건 부족           | 새 요청의 AI에 `모니터 구매요청서 써줘`                                | 수량·예산 보완 안내                                            |

프로필 전환은 시연 기능이며 운영 로그인 검증이 아니다. 새 요청의 대화 분리와 변경 없는 재검토 문서 보존은 PR #3·#4의 취지를 유지한다.

## 시연과 검증의 범위

2026-09-11 화면 개편 검증: 양식으로 3대 요청 생성·선택·문서 생성·제출 취소·제출·담당자 승인, 보완 요청의 의견 필수 동작을 브라우저에서 확인했다. AI 및 반응형 검증 결과와 최신 자동 검사 수치는 [문서 목차](../README.md#현재-검증-상태)에 기록한다.

이 시연 절차는 설계 38개 전체를 클릭으로 재검증했다는 뜻이 아니다. 오류 응답·정확한 금액 경계·문서 실패·중복 토큰·권한 위조는 자동 테스트와 기존 증거로 확인한다. [테스트 추적표](../validation/TEST_TRACEABILITY.md), [과거 브라우저 검증](../validation/BROWSER_QA_REPORT.md), [개발 안내](DEVELOPMENT.md)를 참고한다. 과거 오류 주입용 `runtime/browser-qa/`는 Git 제외 자료다.
