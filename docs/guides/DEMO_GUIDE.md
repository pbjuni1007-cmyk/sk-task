# SK-TASK 실제 화면 시연 순서

2026-09-11 개편 화면 기준이다. 전체 카탈로그는 12개다. 고정 상품 시연은 클라인즈 114,000원·LG 27MS500 169,000원, 무료배송인 모의 자료를 사용한다. 상품 자료를 바꾸면 아래 기대 금액도 다시 확인한다.

## 시연 전 준비

1. [프로젝트 README](../../README.md)에 따라 앱을 실행한다.
2. AI 시연에는 프로젝트 `.env`의 유효한 OpenAI 키가 필요하다. 양식 작성·규정 계산·문서 생성은 AI 연결 없이도 사용할 수 있다.
3. 기본 시연에서는 희망 사양을 비워둔다. 상품 근거에 없는 사양을 입력하면 제출이 제한될 수 있다.
4. 구매 목적에 `시연-정상`, `시연-예산초과`처럼 구별할 이름을 적는다.
5. 왼쪽 아래 **시연 설정 → 시연 프로필 · 인증 아님**에서 역할을 바꾼다.

| 화면의 사용자       | 내부 프로필 | 역할        |
| ------------------- | ----------- | ----------- |
| 박직원 · 개발팀     | employee_a  | 요청 직원 A |
| 김직원 · 운영팀     | employee_b  | 요청 직원 B |
| 이담당 · 구매팀     | buyer_a     | 구매 담당자 |
| 최승인 · 경영지원팀 | manager_a   | 추가 승인자 |

실제 주문·결제·사내 시스템 전송은 하지 않는다. 제출과 결재는 로컬 SQLite에 기록된다. [상품 자료](../reference/COUPANG_FIXTURES.md)와 [API 계약](../reference/COUPANG_API_CONTRACT_CHECK.md)을 참고한다.

## 화면 길찾기

- **내 업무**: 내가 처리할 요청과 최근 생성한 내 요청 5건.
- **+ 새 구매요청**: 새 양식과 새 AI 대화 시작. 기존 요청을 다시 여는 버튼이 아니다.
- **내 구매요청**: 검색·부서·제출일 필터로 내 요청 찾기.
- **결재 대기**: 구매 담당자와 추가 승인자에게만 표시.
- **완료 문서**: 승인 완료·반려 요청 조회.
- **구매요청 상세**: 구매 조건 → 상품 선택 → 검토 및 제출. 오른쪽 AI 도우미와 같은 요청을 수정한다.
- **결재 검토**: 담당자가 문서와 금액을 확인하고 승인·보완 요청·반려한다.

AI 패널은 **AI 도우미** 스위치로 접을 수 있다. 같은 브라우저 세션에서 목록으로 나갔다가 요청을 다시 열면 그 요청의 대화가 남는다. 새로고침·서버 재시작 뒤에도 남는 것은 DB의 업무 데이터이며 대화는 아니다. 사용자 전환·화면 이동은 대기 중인 제출 확인을 취소한다.

## 1. 주 시연: Agent가 구매요청을 완성하는 과정

발표에서는 이 순서를 먼저 진행한다. 직원은 AI로 조건을 전달하고, Agent의 도구 실행과 서버 계산 결과를 확인한다. 직접 입력과 결재 화면은 보조 경로 및 사람의 책임을 보여 주는 데 사용한다.

| 구간                             | 보여줄 LangChain 개념                      |
| -------------------------------- | ------------------------------------------ |
| 조건 수집·상품 탐색              | `create_agent`, Tool 선택, 구조화 출력     |
| 팀 예산 조회·상품 선택·문서 작성 | 서버 Context, 여러 도구의 순차 실행        |
| 후속 수량 변경·예산 보완         | 대화 상태, 업무 버전, 규정 가드레일        |
| 제출 확인·취소·재개              | HumanInTheLoopMiddleware, interrupt/resume |
| 동의한 선호 재사용               | 사용자별 Store                             |

### A. 예산 없는 탐색 → 팀 예산 → 문서 생성

1. **박직원 → + 새 구매요청**. AI에 다음 문장을 보낸다.

   > 우리 부장님 모니터 바꿔야함. 제일 비싼걸로 1개 구매요청서 만들어줘. 목적은 시연-Agent 부장님 모니터 교체야.

2. 처리 중 **구매 조건 저장 / 상품 검색** 표시를 관찰한다. 완료 후 대화 영역의 **최근 실행 내역**을 펼치면 호출한 도구 이름을 볼 수 있다. 수량 1대·목적이 유지되고 예산만 추가로 필요한지 확인한다. 상품 탐색 단계에서는 정식 요청이 생성되지 않는다.
3. 같은 AI 대화에 보낸다.

   > 우리 팀 예산을 확인하고 이번 구매 예산은 50만원으로 설정해줘. 앞서 찾은 LG전자 WQHD 울트라와이드 모니터 34U620B가 예산 이내면 그 상품을 선택해 문서 3종을 만들어줘. 제출하지마.

4. 실습용 개발팀 예산의 **건별 한도 500,000원**과 LG **34U620B 1대 399,000원**, 남은 예산 **101,000원**, 문서 3종을 확인한다. 이는 등록 후보 안에서의 선택이며 실제 회계 잔액은 아니다.

### B. 후속 수정 → 가드레일 → 보완

1. 같은 대화에서 보낸다.

   > 선택 상품과 목적, 예산은 유지하고 수량만 2대로 바꿔줘. 다시 검토하고 문서 3종을 만들어줘. 제출하지마.

2. 총액 **798,000원**, 예산 **500,000원**, 초과 **298,000원**을 확인한다. 문서는 생성되지만 **제출 버튼 근처의 보완 안내와 제출 불가 상태**가 유지되어야 한다.
3. 같은 대화에서 보낸다.

   > 상품과 수량, 목적은 유지하고 이번 구매 예산을 90만원으로 수정해줘. 다시 검토하고 문서를 만들어줘. 제출하지마.

4. 총액 **798,000원**, 남은 예산 **102,000원**, 새 버전의 제출 가능 상태를 확인한다. 명시적인 구매 예산 수정이며 부서 모의 잔액 자체를 변경하는 동작은 아니다.

### C. 사람 확인 → 취소 → 다시 제출

1. AI에 `제출해줘` → **구매요청 제출 확인** 창. 상품·수량·총액·버전을 확인하고 **취소**한다.
2. 문서는 유지되고 제출되지 않았는지 확인한다.
3. 다시 `제출해줘` → 같은 내용을 확인한 뒤 **제출**한다.
4. **구매팀 검토 중** 상태를 확인한다. 이담당으로 전환해 아래 공통 결재 절차를 진행한다. Agent가 담당자 승인을 대신하지 않는다는 점을 설명한다.

### D. 사용자 선호 Store — 짧은 보충 시연

1. 박직원의 새 구매요청에서 **상품 비교 선호 기억하기**를 체크하고 AI에 보낸다.

   > 상품 비교는 가격 우선, 답변은 상세하게 하는 걸 기억해줘.

2. **+ 새 구매요청**으로 새 대화를 열고 정상 구매 조건을 입력한다. 가격 우선 후보와 상세 응답에 수량·예산·총액이 반영되는지 확인한다. 새 대화에는 이전 채팅 원문이 없어야 한다.
3. 김직원으로 전환하면 박직원의 선호가 적용되지 않아야 한다. 단순히 두 결과의 순서가 우연히 같다는 이유로 저장 성공을 판단하지 않고, 필요하면 선호 저장 자동 테스트를 근거로 함께 설명한다.

AI 응답은 변동될 수 있다. 각 단계에서 실제 선택 상품과 금액을 확인하고 진행한다. 오류가 나면 오류 코드·문의 번호와 바로 앞 입력을 기록한다. **AI 시연 성공으로 간주하고 직접 입력으로 대체하지 않는다.** 운영상 진행이 필요하면 문서 아래 **구매팀에 제출**로 별도 처리할 수 있지만 AI 경로와 구분한다.

## 2. 보조 시연: 양식으로 정상 구매요청

1. **박직원 → + 새 구매요청**. AI 도우미는 접어도 된다.
2. 수량 `3`, 예산 `600000`, 구매 목적 `시연-정상 신입 개발자 장비 지급`, 희망 사양 비움.
3. **저장하고 상품 찾기** → 클라인즈 카드의 **이 상품 선택**.
4. 필요하면 **쿠팡 상품 보기**, **가격·사양 상세**를 확인한다. 외부 페이지의 현재 가격은 모의 자료와 다를 수 있다.
5. **검토하고 문서 만들기 →**. 총액 **342,000원**, 예산 **600,000원**, 남은 예산 **258,000원**.
6. **구매요청서 / 상품 비교표 / 규정 검토**를 읽고 **구매팀에 제출 → 제출**.
7. 아래 공통 결재 절차로 **승인 완료**까지 확인한다.

### 공통 결재 절차

1. **이담당 → 결재 대기 → 대상 요청 열기**. 요청이 많으면 제목으로 조회한다.
2. **결재 검토**에서 금액과 문서를 확인한다.
3. **승인 → 확인 창의 승인**. 승인은 의견 없이 가능하다.
4. 일반 요청은 **승인 완료**, 100만 원 이상 요청은 **추가 승인 대기**가 된다.

문서 탭의 **다운로드**는 저장된 Markdown 문서를 받는다. 화면 미리보기는 같은 요청의 구조화 데이터를 읽기 좋게 표현하며, **저장된 문서 보기**에서 다운로드 대상의 원문을 확인할 수 있다.

## 3. 예산 초과 → 수정 → 과거 버전

1. 새 요청: 수량 `4`, 예산 `400000`, 목적 `시연-예산초과`.
2. **저장하고 상품 찾기 → 클라인즈의 이 상품 선택 → 검토하고 문서 만들기 →**.
3. 총액 **456,000원**, 남은 예산 **-56,000원**, 예산 초과 안내와 비활성화된 **구매팀에 제출** 확인.
4. **구매 조건 보완 → 예산 500000 → 구매 조건 저장 → 검토하고 문서 만들기 →**.
5. 제출 가능 상태를 확인한다.
6. **요청 정보 · 이전 버전 → 조회 버전**에서 변경 전 버전을 선택한다. 과거 문서가 보존되고 AI 입력·제출·수정 버튼이 없어야 한다. 이후 최신 버전으로 돌아온다.

## 4. 100만 원 이상 → 추가 승인

1. 새 요청: 수량 `6`, 예산 `1100000`, 목적 `시연-추가승인`.
2. **저장하고 상품 찾기 → LG 27MS500 카드의 이 상품 선택 → 검토하고 문서 만들기 →**.
3. 총액 **1,014,000원** → **구매팀에 제출 → 제출**.
4. **이담당 → 결재 대기 → 열기 → 승인**. 추가 승인 안내 확인 → 확인 창의 **승인**.
5. **추가 승인 대기** 확인.
6. **최승인 → 결재 대기 → 열기 → 승인 → 확인 창의 승인**.
7. **승인 완료** 확인. 구매 담당자의 승인만으로 끝나면 안 된다.

## 5. 보완 요청·반려·사용자 분리

| 항목                | 화면 조작                                                               | 기대 결과                                                      |
| ------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------- |
| 목적 없는 초안      | 양식에서 목적을 비우고 상품 선택·문서 생성                              | 문서가 있으나 제출 불가                                        |
| 목적 보완           | **구매 조건 보완** → 목적 입력 → 저장 → 문서 재생성                     | 새 버전에서 제출 가능                                          |
| 보완 요청           | 직원 제출 → 이담당으로 열기 → **보완 요청**                             | 의견이 비면 확인 창의 **보완 요청** 비활성화                   |
| 보완 후 재제출      | 의견 입력·처리 → 박직원 **내 업무**에서 열기 → **구매 조건 보완**       | 담당자 의견 표시, 수정 후 재검토·재제출 가능                   |
| 반려                | 이담당으로 제출된 요청 열기 → **반려** → 의견 입력 → 확인 창의 **반려** | 반려 상태와 처리 의견 보존                                     |
| 사용자 분리         | A의 요청 제목을 기록 → 김직원 **내 구매요청**에서 조회                  | A의 요청이 목록에 보이지 않음                                  |
| 새 요청의 대화 분리 | 대화 후 **+ 새 구매요청**                                               | 새 화면에 이전 대화 없음. 기존 요청을 다시 열면 해당 대화 유지 |
| 지원 범위 밖        | 새 요청의 AI에 `점심 메뉴 추천해줘`                                     | 모니터 구매 지원 범위 안내                                     |
| 조건 부족           | 새 요청의 AI에 `모니터 구매요청서 써줘`                                 | 수량·예산 보완 안내                                            |

프로필 전환은 시연 기능이며 운영 로그인 검증이 아니다. 새 요청의 대화 분리와 변경 없는 재검토 문서 보존은 PR #3·#4의 취지를 유지한다.

## 시연과 검증의 범위

2026-09-11 화면 개편 검증: 양식으로 3대 요청 생성·선택·문서 생성·제출 취소·제출·담당자 승인, 보완 요청의 의견 필수 동작을 브라우저에서 확인했다. AI 및 반응형 검증 결과와 최신 자동 검사 수치는 [문서 목차](../README.md#현재-검증-상태)에 기록한다.

이 시연 절차는 설계 38개 전체를 클릭으로 재검증했다는 뜻이 아니다. 오류 응답·정확한 금액 경계·문서 실패·중복 토큰·권한 위조는 자동 테스트와 기존 증거로 확인한다. [테스트 추적표](../validation/TEST_TRACEABILITY.md), [과거 브라우저 검증](../validation/BROWSER_QA_REPORT.md), [개발 안내](DEVELOPMENT.md)를 참고한다. 과거 오류 주입용 `runtime/browser-qa/`는 Git 제외 자료다.

## 진행 표시와 오류 확인

AI 패널은 데스크톱에서 따라다니며 대화 이력만 내부 스크롤로 읽는다. 진행 표시는 실제 모델·도구 실행 이벤트이며, 검증 전 원문을 타자 효과로 출력하는 방식이 아니다. 상품 선택 후에는 고정된 선택 요약과 **검토하고 문서 만들기 →** 버튼을 사용한다.

오류 메시지의 **오류 코드 / 문의 번호**를 기록하면 서버 로그의 같은 번호와 대조할 수 있다. 로그에는 허용된 오류 코드와 예외 종류만 남기며 모델 원문·상품 본문·API 키를 남기지 않는다. 이 기록 보완 자체가 이전 간헐적 제출 오류의 원인을 해결했다는 뜻은 아니다.
