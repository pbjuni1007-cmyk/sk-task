# SK-TASK 브라우저 검증 보고서

> 과거 실행 기록이다. 이후 PR 수정 및 현재 자동 검사 결과는 [문서 목차](../README.md#현재-검증-상태)를 확인한다. 이 보고서의 관찰 결과와 원본 자료는 당시 기준으로 보존한다.

검증일: 2026-09-10 · 도구: Chrome / CUA 브라우저 조작 · 기준: 설계 테스트 38개.

**38개 시나리오를 아래 방식으로 실행·대조했다. 업무 흐름을 막는 미해결 오류는 발견하지 않았고, LG 판매자 오표기 1건을 수정했다.** 모든 항목이 실제 외부 API 호출이나 일반 화면만으로 검증됐다는 뜻은 아니다. 다운로드 저장 완료는 별도 미확인이다.

## 검증 범위와 환경

- **U 14개**: 앱 화면 직접 조작. 실제 AI 대화, 문서 탭, 제출·취소·결재, 사용자 전환과 실제 상품 링크 확인.
- **I 20개**: 별도 DB에 오류·합성 가격·모델 응답을 주입하고 같은 앱 화면을 직접 조작.
- **C 4개**: 일반 화면에 없는 API 인자와 동일 토큰 재전송을 별도 브라우저 QA 콘솔에서 실행.
- 기준 커밋: `33ff184bb98f32cc97e79b84f8f5462db2c5c37e`. 검증 중 변경은 판매자 출처 자료와 문서·테스트 보관물이다. 업무 Python 코드 변경은 없다.
- 정상 앱은 `127.0.0.1:8502`, 주입용 앱은 `127.0.0.1:8503`에서 실행했다. 기존 8501 사용자 DB와 `.env`는 변경하지 않았다. 판매자 정정은 동일한 원본 상품 자료에도 반영했다.

## 주요 결과

- 클라인즈 3대 342,000원 → 4대 456,000원 수정, 목적·선택 보존, 확인 후 제출, 취소와 승인 흐름 확인.
- LG 6대 1,014,000원 요청은 구매팀 → 추가 승인자까지 처리되어 최종 승인 완료.
- 499,999/500,000원, 999,999/1,000,000원 경계 및 주문당·개당 배송비를 포함한 예산/승인 규정 확인.
- 500·timeout·403·429, 가격 누락, 빈 검색, 허위 가격·상품 ID, 상품명 지시문, 반복 호출, 구조화 응답 오류, 문서 생성 오류를 주입해 안전한 종료 확인.
- 정상 실제 AI **20/20 성공**. p50 **6.602초**, p95(최근접 순위) **7.197초**, 최대 **8.402초**. 모두 모델 6회·도구 5회. 이 시간은 화면에서 실행한 Agent의 처리 시간이며 브라우저 초기 로딩 시간은 제외한다.
- 생성된 20개 요청의 저장 문서도 읽어 요청번호·버전·수량 3·단가 114,000원·총액 342,000원 일치와 미제출 상태를 추가 대조했다.

## 수정한 문제

LG 상품 페이지의 판매자 정보는 **쿠팡**, 제조사는 **LG전자**였다. 기존 `판매자 LG전자`를 `판매자 쿠팡`으로 수정했다. 원래 사용자 제공 값은 `user_reported_seller`에 보존하고 `browser_follow_up`에 확인 근거를 추가했다. 화면의 `27MS500 · 판매자 쿠팡`을 재확인했으며 관련 테스트 **7 passed**다. 최종 전체 자동 회귀도 **114 passed (2.54초)**로 재확인했다.

## 추가 화면 검증

- 희망 사양·구매 목적 예시가 placeholder로 표시된다.
- 상품 미선택 시 적용·문서 생성 버튼이 비활성화된다.
- 요청번호 검색으로 원하는 요청 1개만 조회된다.
- 반려·보완 요청은 사유가 필수다. 처리 확인을 취소하면 상태가 유지된다.
- 보완요청함에서 목적 수정 → 새 버전 문서 → 재제출이 가능하다.
- 반려 후 최신 버전 이력에는 직원 제출과 구매 담당자 반려가 기록된다.
- 과거 버전은 읽기 전용이며 승인·제출 버튼이 노출되지 않는다.

## 미확인 및 후속 UI 개선

1. **다운로드 완료 미확인**: 문서 3종 다운로드 버튼을 눌렀으나 파일 저장 완료는 확인하지 못했다. 브라우저 도구의 URL 보안 정책이 `chrome://downloads/` 접근을 차단했다. 우회하지 않았다. 문서 탭 내용/서버 문서 바이트 검증과 실제 브라우저 파일 저장 성공은 구분한다.
2. 동일 확인 토큰의 순차 중복 제출은 확인했지만 실제 동시 클릭 경합을 UI에서 재현한 것은 아니다.
3. 모델 오류가 `(ValueError)`, `(BudgetExceeded)`로 표시되고, 권한 거절도 지원 범위 안내로 표현된다. 처리 차단은 되지만 사용자에게 원인이 더 명확한 문구로 다듬을 필요가 있다.
4. AI 후보 응답은 상세 화면을 열도록 안내하며 대화 안에 후보 카드를 보여주지 않는다. 제품 시연 전 다듬을 UX 항목이다.
5. 쿠팡 실제 API 호출은 합의된 모의 실습 범위 밖이다. 공식 request-response 본문 대조는 이번에 완료했다.
