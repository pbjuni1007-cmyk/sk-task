# SK-TASK 시연 가이드

실제 OpenAI 모델과 사용자 확인 상품을 사용하며 쇼핑 API는 모의 응답이다. 실제 구매·결제·외부 전송은 하지 않는다. 사내 결재 역시 로컬 SQLite에 기록한다.

## 시나리오 1: 정상 구매 · 기본 양식

1. 요청 직원 프로필에서 구매요청 작성. 수량3, 예산600000, 구매 목적 ‘신입 개발자 장비 지급’. 사양은 비워둔다.
2. 저장하고 상품 찾기 → 클라인즈 선택·적용 → 문서 만들기.
3. 배송비 포함342000원 및 문서3종 확인. 제출 확인 → 제출.
4. 시연 설정에서 구매 담당자로 변경 → 결재대기함 → 승인.

LG 3대는507000원이며 50만원 이상 비교 규정에 따라 서로 다른 후보2개가 필요하다. 두 상품 모두 후보에 있는 모니터 범주 검색을 사용한다.

## 시나리오 2: 예산 초과 · 조건 수정

수량4, 예산400000, 목적 ‘업무용 장비 교체’로 클라인즈 선택. 총액456000원으로 초과56000원, 제출 차단을 확인한다. 구매 조건 보완에서 예산500000원으로 수정하고 다시 문서를 생성한다. 새 버전으로 저장되며 이전 문서는 요청 정보에서 조회 가능하다.

## 시나리오 3: 추가 승인

LG 6대, 예산1100000, 목적 ‘개발팀 모니터 지급’. 총액1014000원. 제출 후 구매 담당자 승인을 해도 추가 결재 대기이며 추가 승인자 승인 뒤 완료된다.

## AI 여러 턴

- “업무용 모니터 3대, 배송비 포함 예산 60만원, 목적은 신입 개발자 장비 지급이야. 모니터 후보를 찾아줘.”
- “클라인즈 상품을 선택하고 문서 3종 만들어줘. 제출은 하지마.”
- “선택 상품과 목적은 그대로 두고 수량만 4대로 바꿔서 검토하고 문서 다시 만들어줘.”
- “제출해줘” → 확인 화면에서 취소 또는 제출.

AI에게 작성만 요청했을 때 업무 제출이 발생하지 않아야 한다. 실제 모델의 선택·응답 품질은 변동 가능하므로 결과 문서를 확인한다.

## 실행·검증

```sh
.venv/bin/python -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501 --browser.gatherUsageStats false
.venv/bin/python -m pytest -q
.venv/bin/python scripts/check_catalog.py --strict
```

실제 모델 평가는 비용이 발생한다. 이미 제공한 키로 실행 가능하며 아래 명령은 실행할 때마다 호출한다.

```sh
.venv/bin/python scripts/evaluate_dialogues.py
.venv/bin/python scripts/evaluate.py --suite acceptance --runs 10 --catalog user-confirmed
.venv/bin/python scripts/evaluate.py --suite latency --runs 20 --catalog user-confirmed
```

`.env`의 OPENAI_API_KEY를 기본으로 사용한다. 인증·접근·한도 오류401/403/429 시 OPENAI_API_KEY_SUB가 있으면 전환한다. 같은 Agent 세션은 보조 키를 계속 사용한다. 실패한 기본 호출도 모델6회 예산에 포함하므로 복잡한 한 턴 작업은 한도에 도달할 수 있다. 두 키 모두 실패하면 종료하며 자동 무한 재시도하지 않는다.

API 예제는 fixtures/coupang/search-request.json 및 search-response.json. 배송/출처 등 내부 정보는 evidence.json에 별도 보관한다. 현재 공식 도움말 동적 본문은 독립 대조하지 못했으며 승인된 설계서 필드 계약을 따른다. 모의 클라이언트의50회/분 제한은 테스트용이며 실제 Search API 사용 한도를 의미하지 않는다.
